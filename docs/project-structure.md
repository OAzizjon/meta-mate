## Rust split: what goes where

| Crate | Rule | Why |
|---|---|---|
| `mm-core` | No `windows` crate, no I/O, no async runtime. Plain functions and state machines. | Unit- and fuzz-testable everywhere (also in agents' sandboxes, which have no desktop). Most bugs live here: MateScript, coordinate transforms, step completion. |
| `mm-platform` | Traits only + `MockBackend` + `ReplayBackend` (reads `fixtures/replay`). | Pointing logic is tested against recorded screens, not a live desktop. A Linux backend can implement the same traits after the hackathon (Windows only for now, D39). |
| `mm-win32` | The only crate that calls Win32/COM/WinRT. Small, boring, behind the traits. | Keeps unsafe and platform code in one place; reviewers know where to look. |
| `src-tauri` | Wiring only: commands, events, channels. No business logic. | Thin shell = easy to replace (WPF fallback plan) and to test the core without Tauri. |

Traits (first draft): `InputHooks` (key + mouse events), `UiTree` (`snapshot`, `element_from_point`), `ScreenCapture` (`capture_target → (image, FrameTransform)`), `Overlay` (robot pose, highlight, hide-for-capture), `InputInjector` (`execute_verified`).

## Twelve conventions

1. **Names in one place.** `APP_NAME` and `ROBOT_NAME = "Mate"` live in `mm_core::constants` and are injected into locales and prompts. The product name may change after the rules.
2. **Coordinate newtypes.** `PhysPx`, `ShotPx`, `CssPx` are distinct types; conversion only through a `FrameTransform`. Mixing them must not compile.
3. **Privacy-safe Debug.** Screenshots, PCM, transcripts and invite codes implement `Debug` as metadata only (`[Screenshot 1280x720 redacted=2]`, `[Transcript 42 chars]`). Logs carry ids, timings and token counts, never content.
4. **Redaction by type.** The network client accepts only `RedactedImage`, which can be built only after password rects were painted or the user said yes. A raw image cannot be sent by mistake.
5. **Refusals are values.** `RefusalReason { TargetNotFound, RedactionUncertain, SafetyBlocked, UiaTimeout, ... }` maps to a localized line ("I can't see that here"). Never `unwrap()` on user-facing paths.
6. **One generation id per question.** Each push-to-talk increments a `generation_id` that travels through ASR, model, TTS and the audio worklet; barge-in drops everything older.
7. **Handwritten IPC.** IPC lives in `src/ipc/` and the page modules in `src/`; `mm check`'s contracts check (`tools/mm_contracts.py`) keeps them aligned: every command registered and called by its name with the right argument names, every event emitted and listened, every locale key present. `tsc --noEmit` runs in `mm check`.
8. **Locales are tested.** `en.json` and `ru.json` must have the same keys and the same `{placeholders}`.
9. **Assets carry licences.** Every sound file has a line in `assets/sounds/LICENSES.md` (`mm sounds` fails otherwise). Pre-recorded MMS-TTS phrases are marked CC-BY-NC-4.0.
10. **Config precedence.** CLI flags > environment (names in `env_keys_names.txt`) > user settings (DPAPI-protected) > `defaults.toml`. Our provider keys never ship in the client; a user may enter their own Meta key (DPAPI), never one of ours.
11. **Demo flags.** `demo-mode` (deterministic fallbacks, warm-up pings) and `dev-fallback-providers` (non-Meta models; off in release builds) are explicit feature flags, not `if` checks scattered around.
12. **Small files, flat modules.** One concept per file, no `utils.rs` grab bags; a module that grows past ~400 lines gets split.

## Agents and the CLI

- Agents work in a copy **without `.git`**, so `mm` switches to agent mode by itself and refuses everything except `mm agent check|test` (offline, no secrets, no GUI). Lead-only commands (`uia`, `art`, `sounds normalize`, `keys`, later `deploy`/`release`) never run there.
- Give agents work in `mm-core` and tests first: it runs anywhere and is where their drafts are most reliable.
- Everything an agent writes is a draft: read the whole patch, run `mm check` and `mm test` yourself.

## Replay fixtures to record before or on day 1

On the Demo Windows user only (no private windows), with `mm uia --save NAME`:

1. Windows Settings → Accessibility → Text size (the main scenario), at 100% and at 150% scaling.
2. Edge with a simple page (and a fresh profile: the cold Chromium tree), plus an open `<select>` dropdown.
3. A right-click context menu on the desktop (a popup outside the window).
4. Telegram Desktop or a canvas page (poor tree → fallback path).
5. A login form with a password field (redaction), twice: (a) hidden, (b) revealed with the eye button. Fake credentials only; `mm uia` refuses the screenshot for both, so these are tree-only fixtures (D37).
6. A "Buy now" / "Delete" button (safety blocklist and refusals).
7. Wikipedia's Appearance panel (Text: Small / Standard / Large): the main "make the text bigger" scenario on the web.
8. The desktop with its icons (Explorer's list view): "open OBS", "where is my folder".
9. A busy social feed with icon-only navigation and ads (e.g. OK.ru, popular with older Russian speakers): pointing at unlabeled icons, never at ads, games or dating offers.

Ideas 7–9 and the revealed-password case come from the owner's screenshots of 2026-10-26 (taken on his own account, so they are not fixtures themselves).
